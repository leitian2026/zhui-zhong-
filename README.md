# TraceLog — LSPosed 调用记录模块

记录目标 App 调用了哪些代码（弹幕绘制、文本、颜色、指定类的方法），
日志在模块自己的界面里查看，可导出成 txt。

## 构建（手动，不会自动构建）
1. 把本压缩包解压，所有文件上传到 GitHub 仓库根目录（注意 `.github/workflows/build.yml` 路径要保留）。
2. 仓库页面 → Actions → **Build Release APK (manual)** → Run workflow。
3. 构建完成后在该次运行页面底部 Artifacts 下载 `TraceLog-release`，里面是已签名、已开启 R8 压缩优化的 release APK。
4. 签名用仓库里固定的 `tracelog.jks`，之后每次构建都能直接覆盖安装。

## 使用
1. 安装 APK，LSPosed 里启用「TraceLog」，作用域勾选目标 App（默认推荐抖音），强杀目标 App。
2. 打开 TraceLog，填目标包名、关键字，点「保存并推送配置」（root 授权）。
3. 在目标 App 里发一条包含关键字的弹幕，回 TraceLog 点「查看日志」。
   日志里的 `TEXT` 记录带调用栈，栈里的类/方法就是弹幕渲染代码（混淆名也能用来 hook）。
4. 想知道颜色是在哪设置的：开「颜色追踪」，颜色栈过滤填上一步看到的弹幕类名片段，再触发一次。
5. 想看某个类每次调用的参数/返回值：在「指定类追踪」里填 `类名` 或 `类名#方法名`。
6. 日志页：刷新 / 导出（保存成 txt）/ 复制 / 清空，可按关键字过滤。

## 原理
- Hook 在目标 App 进程内，把日志写进目标 App 自己的数据目录 `files/tracelog/`；
  模块界面通过 root 读取。配置同理由模块界面通过 root 写进去。
- 全程事件驱动：没有轮询、没有常驻后台。配置在目标 App 事件触发时检查文件修改时间（≤2 秒一次），变了才重读。
- 同一个调用位置默认只记 3 次，防止每帧重复绘制把日志刷爆；日志文件超过 4MB 自动轮转。
