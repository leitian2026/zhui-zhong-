# TextRec 使用说明（给 AI 读的）

> 你是被用户叫来帮他用 TextRec 的 AI。先读完「0. 硬规则」和「1. 这是什么」，再按「2. 用户想找什么 → 怎么配」查表。
> 其余章节是查阅用的：功能清单（第 7 章）、配置字段（第 8 章）、记录页命令（第 9 章）。
> 本文不依赖源码就能用；字段名和源码 `RecConfig.java` 的 public 字段名一致，以源码为准。

---

## 0. 硬规则（每次都要照做）

1. **只要用户要研究的操作不止一个（两个及以上），就必须让他用任务浮窗，并且你必须同时给出任务清单。** 不要只给配置。任务清单是浮窗一步一步提示的依据，也是导出里「按任务阶段」分账的依据；没有它，记录里所有操作混在一起，分不清哪条属于哪个操作。
2. **你的回复里必须有一整块「可直接粘贴」的文本**：采集配置（`key=value`）和任务清单（`名称|提示|秒数`）写在同一个代码块里，用户整块复制，粘贴进首页最上面的「粘贴配置和任务清单」框，点「回填并保存」或「打开浮窗」。不要拆成两次让用户分开粘贴。
3. 只有一个操作、且不需要分阶段时，才可以不要任务清单；这种情况要在回复里明说"这次只有一个操作，所以没写任务清单"。
4. 提醒用户：**配置粘贴后只是回填表单，还没生效**，要点首页底部「应用并重新记录」（需要 root）。要记冷启动阶段的文字，必须强杀目标 App 再启动。
5. 本模块**只读**，不会修改目标 App 的任何东西。要改颜色、隐藏元素，那是另一个模块的事；本模块只负责找出"该 hook 哪个方法"。
6. 没在真机上验证过的功能要如实说，不要说成"肯定能用"。
7. **配置里每个字段必须写在同一行**（一行 `key=value`）。多个关键字不能折成多行，否则后面几行会被当成任务清单：普通模式用逗号隔开（`keywords=福利,红包`），正则模式（`regex=true`）只能用转义的换行 `\n` 隔开（`keywords=\\d+小时前\n昨天`）。多行的 `traceMethods` 同理，用 `\n` 或行尾反斜杠续行。
8. **不要留占位符**：配置里不能出现"你的地名"这类没替换的占位文字，不知道的内容就别写，改用全量模式（`keywordMode=false`）先抓一遍。
9. **多行的列表型配置项（`traceMethods`、`keywords` 等）用行尾反斜杠续行时，续行是把下一行直接接在后面，不会补换行。** 每一条末尾必须先写 `\\n` 再写反斜杠（`类#方法 @count\\n\\`），或者整个配置项写在一行里用 `\\n` 隔开。模块 1.30.0 起会校验并指出这类错误，但你给出的文本最好一次就写对。

## 1. 这是什么

TextRec 是一个 LSPosed 模块（需要 root），挂进目标 App（默认抖音 `com.ss.android.ugc.aweme`），**只观察**，回答这类问题：

- 屏幕上这段文字是**谁设置的**（`setText` 的调用栈）、**谁画的**（`drawText` 的调用栈）
- 这个图标是谁设置的
- 这个文字颜色是谁设的
- 某个方法每次被谁调用、参数和返回值是什么
- 某个控件的透明度 / 可见性 / 选中态是谁改的
- 进度、时长这类状态存在哪个对象的哪个字段

并且给出能直接拿去写 hook 的方法签名，标明 **[稳定]**（名字没被混淆，换版本大概率还能用）还是 **[混淆]**（换版本会变）。

两个 App 界面：**首页**（决定采集什么、把配置推给目标 App）和**记录页**（看、筛、导出记录；浮窗、标记、基线、时间线也在这里）。

## 2. 用户想找什么 → 怎么配（先查这张表）

| 用户想找 | 采集开关怎么开 | 方法追踪 | 备注 |
|---|---|---|---|
| 某段文字是谁设置 / 谁画的 | 「只记文字」预设：`traceSet` `traceDraw` `traceColor` `autoParams` 开，其余关；`keywordMode=true` + `keywords=那段文字` 能大幅缩小范围 | 不填 | 最常用；全量模式会拖慢目标 App，只在调试时开 |
| 文字颜色是谁设的 | `traceSet` `traceDraw` `traceColor` `autoParams` 开 | 不填 | Compose 文字靠 `autoParams` 自动观察画笔参数，记录里能看到描边 / 填充颜色 |
| 按钮图标（没有文字）是谁设的 | `traceIcons=true`，其余可关 | 不填 | 记录里有资源名、Drawable 类型、缩略图 |
| 某个方法被谁调用、参数返回值 | 其余全关，或保持 `traceExclusive=true`（默认，自动关） | 填 `类#方法` | 见第 5 章 |
| 视频进度 / 总时长存在哪 | 同上 | 填疑似方法，加 `@tag=` 视需要；打开 `traceDump=true`；`valueClock=true` 只记带 `00:00` 的调用 | 把进度条拖到两端，看 min/max 判断单位 |
| 一块界面里有哪些控件、谁在谁里面、是什么布局（视图树） | `viewDump=true`，其余开关随意；`viewDumpKey` 填那块区域里某个控件的类名或 id 里的词（默认抖音视频文案的两个类） | 不填 | 1.27.0。任务开始 / 结束、记录页点「标记」时各抓一份，导出里有「视图树」一节。需要写任务清单（一个视频一件事）；没在真机上验证过 |
| 不知道控件叫什么，只知道它在屏幕上哪里 | `viewTap=true`；要「设置自」就开着 `traceSet` 并把 `traceExclusive` 关掉 | 不填 | 1.28.0。点一下那个位置，导出里有「点击 #n」：这个点上所有控件从外层到最上层。没在真机上验证过 |
| 想知道 Aweme 这类对象被哪个容器持有 / 哪个钩点最稳 / 哪个操作独有哪些方法 | 默认就开着 `annotFrames` `annotOwners` `annotSweep`；方法追踪要追带 Aweme 参数的方法才有「对象归属」 | 填 `类#方法` | 1.29.0。导出里看「对象归属」「任务对比」「分叉帧」三节，调用栈每帧后面的〔…〕标签，以及记录里的「钩点评级」。没在真机上验证过 |
| 想找「判断状态的钩子」（比如是否已点赞）/ 想知道是谁改了某个字段 | 追踪带该对象参数的方法；`treeOn` `watchAuto` 默认开 | 任务清单写成「对照（单击）空 / 点赞 / 取消赞」，要比较的每件事里都做 | 1.31.0。导出看「值差异」（✦ 节点）、「观察点变化」（写入者）、「候选钩点排名」「钩子草稿」。想盯某个具体字段就写 `watch=类#方法:路径` |
| 想区分「必经」和「偶发」的方法 | 任务清单第 4 段写 `x3` | `点赞\\|双击视频点赞\\|\\|x3`（竖线前不要加反斜杠，这里只是表格转义） | 浮窗会让同一件事连做 3 遍，导出里每条记录写出现在几/共几遍 |
| 某控件透明度 / 可见性谁改的 | `traceState=true`；或在 `viewFilter` 填控件类名 / id，任何控件的变化都会记 | 可追 `android.view.View#setAlpha` 等 | 变体里带控件当前文字 |
| 拖动才出现的文字（平时不可见） | `traceSetOnly=true` | 不填 | 记录里给出"没被画的原因" |
| 弹幕 / 评论等 Compose 文字 | `drawCompose`、`autoParams`、`composeDump` 开 | 可追 `androidx.compose.ui.text.MultiParagraph#paint-LG529CI` | Compose 没有 View，没有"设置栈" |
| 异步是谁投递的 | 方法追踪 + `chainOn=true` | 必须有一个锚点方法 | 链路追踪，采样记录，会拖慢，用完关掉 |
| 一个界面里谁在持续调用（找噪声） | 在记录页用「基线」录一段什么都不操作的时间 | | 基线里也在调用的位置会被标记为噪声 |

**拿不准就这样起步**：`keywordMode=true`、`keywords=用户看到的那段文字`、`traceSet=true`、`traceDraw=true`、`traceColor=true`，其余关；再写任务清单。第一次记不到再放宽。

## 3. 标准流程（告诉用户按这个走）

1. 一次性准备：LSPosed 里启用模块，作用域勾目标 App；给 TextRec 授 root；浮窗要给「显示在其他应用上层」权限（首次点打开浮窗时会跳到设置）。
2. 把你给的那一整块文本粘进首页最上面的框，点「回填并保存」。配置回填进下面的表单，任务清单存起来。
3. 检查一遍表单，点首页底部「应用并重新记录」（推送配置 + 清空旧记录）。只想改设置不清记录，用流程卡片里的「只应用设置，不清空记录」。
4. **强杀目标 App 再启动**，切到要研究的界面，让视频已经在播。
5. 回 TextRec 点「打开浮窗」（首页顶部，或粘贴框旁），浮窗停在「准备」；切回目标 App，点浮窗 ▶ 开始。
6. 照浮窗提示一件一件做。每件事结束浮窗会自动检查有没有记录到，记到会变绿色「已记录完成 ✓」，点 ▶ 下一件。下一件要翻好几个界面，就点「⏸ 暂停记录」，翻到了再点「▶ 开始记录」。
7. 全部完成后，回 TextRec「查看记录」，筛选、导出。给 AI 看的首选导出是**「任务清单的记录（txt）」**。

注意：任务开始 / 结束标记经 root 写文件、目标进程再读，有零点几秒延迟。点开始后**等一秒再操作**，结束后的最后一点动作可能还算在这件事里。

## 4. 任务清单怎么写

一行一件事，格式 `名称|提示|秒数|空`（后三项可省）。第 4 段写 `空` = 对照任务，允许这件事记到 0 条记录（例如方法追踪独占时，「单击一次」这种本来就不会调到被追踪方法的对照操作，写成 `单击一次|提示||空`；不写的话 0 条记录会判未通过）。

| 写法 | 含义 |
|---|---|
| `名称\|提示\|` | 普通任务，用户做完等浮窗自动判断结束，或点「提前结束」 |
| `名称\|提示\|40` | 带秒数：到点自动结束（适合"别操作，让它自己滚 40 秒"） |
| `@基线\|提示\|10` | 基线：什么都不操作，开始自动发"基线开始"，倒计时结束自动发"基线结束"；期间被调用的位置会被标为"基线里也在调用"（周期性噪声） |
| `!名称\|提示\|` | 只对**第一件**有意义：浮窗一打开就直接开始，用于要在目标 App 还没运行时就开始的任务（冷启动） |
| `// 注释` | 整行忽略 |

**怎么写好：**
- 一件事 = 一个能单独区分的用户动作。划一次、点一下、拖一下、进评论再返回，各一件。不要把"划视频、暂停、继续"揉成一件。
- **提示要写成用户照着做的动作**："点一下视频暂停，停 3 秒"，不要写"测试暂停"。
- 第一件通常放基线（10 秒），后面的任务才能和噪声对比。
- 有需要等的动作写秒数，别让用户盯着空等。
- 任务名里别用 `|`；任务名恰好像 `xxx=` 时，在任务清单前单独写一行 `[任务清单]`。

**可直接用的例子：**
```
@基线|什么都不要操作，手离开屏幕，让视频正常播放|10
划到下一个视频|向上划一次，等新视频开始播放||
暂停|点一下视频暂停，停 3 秒||
继续播放|再点一下继续播放||
拖进度条回退|按住进度条往左拖一段再松手||
进评论再返回|点评论图标，等评论出来，再按返回||
弹幕密集 40 秒|进弹幕密集的直播间 / 视频，别操作，让弹幕自己滚 40 秒|40
```

浮窗上有：✕ 关闭、↺ 重做（这一件重来，上一次作废）、◀ 上一件、▶ 提前结束 / 下一件。浮窗里**绿色面板是正在做的任务，灰蓝色面板是下一件**（提前准备用）。按住浮窗顶部文字可拖动。

**一份完整的「可粘贴」回复长这样**（配置在前，任务清单在后，同一个块）：
```
keywordMode=true
keywords=福利,红包
traceSet=true
traceDraw=true
traceColor=true
autoParams=false
traceIcons=false
traceSetOnly=false
traceState=false

@基线|什么都不要操作，让视频正常播放|10
划到下一个视频|向上划一次，等新视频开始播放||
点进评论再返回|点评论图标，等评论出来，再按返回||
```
程序按行区分：以 `英文标识符=` 开头的是配置行（行尾反斜杠表示续行），其余非空行是任务行。

## 5. 方法追踪（最灵活，要记住的规则）

首页「高级 → 方法追踪」，或配置字段 `traceMethods`，**每行一项**：

| 写法 | 含义 |
|---|---|
| `类全名#方法名` | 追踪这个方法的**所有重载** |
| `类全名#<init>` | 追踪构造方法 |
| `类全名#*` | 追踪这个类**自己声明**的全部方法和构造方法（跳过抽象 / native / 合成）；调用很多，配合排除名单和触发窗口 |
| `子类#方法`，方法声明在父类 / 接口 default | 自动挂到声明处，用 `this` 过滤，只记 this 是该子类的调用；记录仍按你写的「子类#方法」归档 |
| `android.view.View#setAlpha` 这类系统类 | 支持；变体里会带 `this`（View 显示为 `类#id「文字」`），能看出是哪个控件 |
| `// 开头` | 注释 |
| 行尾 `@count` | 只计数，不记参数、不抓栈（高频方法用） |
| 行尾 `@args` | 只记参数 / 返回值变体，不抓栈 |
| 行尾 `@stack=4` | 这一行单独的栈深度 |
| 行尾 `@every=10` | 这一行单独的抽样间隔 |
| 行尾 `@tag=N` / `@tag=ret` | 取第 N 个参数（从 0 数）/ 返回值当"当前标识"（如视频 id），记录和时间线都带它。只认字符串和整数，浮点不算 |
| 行尾 `@seq` / `@seq=N` | 序列模式（1.32.0）：任务里这个方法**每一次**调用都按先后记一条时间线事件（kind=SEQ：毫秒、线程、参数→返回值、耗时、栈顶 5 帧），不合并、不抽样。每个方法每个任务阶段默认最多 200 条（`@seq=N` 改，上限 1000），全部方法合计每阶段 1500 条；超出的只计数，导出头部写明丢了多少。时间和序号是**进入方法时**的，外层方法排在它里面调用的方法前面 |

行里写了括号参数（如 `类#方法(int)`）会被去掉，**所有同名重载都追**。

**要点：**
- **独占开关 `traceExclusive`（默认开）**：填了方法追踪时，目标 App 里自动把文字 / 图标 / 颜色 / 状态 / 绘制 / Compose 观察全部当成关闭，记录里只剩方法追踪，更干净。只改运行时副本，界面开关和配置文件不动，清空方法清单后自动恢复。想让方法追踪和其他记录一起记，设 `traceExclusive=false`。
- **方法追踪和普通记录走同一套任务内 / 任务外逻辑**，可以和浮窗一起连续做多个任务。
- 类还没加载时进入相关页面后会自动重试（最多 40 次）；装不上的原因显示在记录页顶部的 ⚠ 里（类没找到 / 方法不存在 / hook 失败）。
- 追踪每秒调用上千次的方法会拖慢目标 App；超过 3000 次后自动降为每 10 次取一次样。打开「压低高频方法」（`quietCount`）更稳。
- 混淆名换版本会变；每个快照带 App 版本号。
- 只对方法追踪生效的辅助项：`windowMs`（触发窗口）、`excludeInfra`、`valueClock`、`valueFilter`、`excludeList`、`quietCount`、`traceDump`（含 `traceDumpEvery` `traceDumpLines` `traceDumpDepth`）。
- 方法追踪的记录里有：调用栈（谁调用了它）、参数→返回值的各种取值变体、this 的对象身份、钩点信息（重载、final / 静态 / 抽象、是否疑似混淆、类加载器、第几次尝试时可用）。

**看先后顺序、看谁取消了延迟消息（1.32.0）：**

- 采样事件每个位置只留前 5 次且相同的合并，看不出先后。要判断「先取消再点赞」还是反过来，就在关心的方法行尾写 `@seq`，导出时间线里按毫秒 + 序号读 SEQ 行。采样计数现在按任务阶段各自重新数，不会被上一个任务的噪声提前用光。
- 取消类方法写成 `android.os.MessageQueue#removeMessages @seq`、`android.os.MessageQueue#removeCallbacksAndMessages @seq`（`removeEqualMessages` 同理；Handler / WeakHandler 的取消最终都走这里，不要再同时写 Handler 上的同名方法，会重复）。SEQ 行里 `⟦…⟧` 是被取消的待处理消息：what、callback、还差多少毫秒执行、投递于多久前、投递线程和投递栈。
- 查「是谁投递的」需要开 `chainOn` + `chainAsync`（投递时才记来源，且每秒只抓前 300 条，漏了会写「没有找到匹配的待处理消息」）。没开会明确写出来，不会假装查过。
- 看投递：`android.os.MessageQueue#enqueueMessage @seq`（参数里的 Message 带 when / what / target）；看执行：对应 Handler 的 `handleMsg` / `handleMessage` 写 `@seq`。高频方法务必配「触发窗口」或值过滤，不然 200 条很快用在噪声上。

**例：找评论列表项被谁调用：**
```
traceMethods=com.ss.android.ugc.aweme.comment.CommentItemView#setData
windowMs=1500
excludeInfra=true
quietCount=50
```

## 6. 读结果

记录页（首页点「查看记录」）：每条记录一张卡片：圆点（绿=在屏幕上，灰=不在，橙=未知）、类型标签、次数、文字、缩略图、页面 / 容器 / 控件，最下面是设置位置和绘制位置。点进详情有页签：概览 / 设置栈 / 绘制栈 / hook 签名；底部「复制全部」「复制可 hook 签名」。

**导出**（右上图标）：
- **任务清单的记录（txt）**：首选。只含任务内、在任务清单上任意一件事期间被调用的记录，不看当前筛选；文件头列出全部任务，并写明哪几件事期间一条记录都没有；每条有「按任务阶段的调用次数」，如 `任务2 12  任务3 0  任务4 31`。想只看某一件事，导出后搜 `任务3`。
- hook 清单：每个控件只写"它是什么 + 可以 hook 的方法（由近到远 3 个，标稳定 / 混淆）"。
- 完整 txt（给人看）、JSON（字段固定，`schema:1`，给后续 hook 模块用）、HTML（含图标缩略图）。
- 「精简模式」：txt 不写绘制栈和颜色设置栈。

**怎么判断一个 hook 点能不能用：**
- `[稳定]` 业务帧：名字没混淆，首选。
- `[稳定·通用控件]`（`AppCompatImageView` / `DmtTextView` 等）：hook 后必须按 View 类 / id 过滤。
- `[稳定·通用基础设施]`（消息分发、LiveData、异步包装）：永远不推荐。
- `[混淆·换版本会变]`：能用，但换版本要重新记。
- `⚠ 共用×N`：同一个 hook 出现在 3 条以上记录里，是通用入口，不能单独定位某个控件。
- 没有稳定帧时，会给系统方法兜底（`TextView#setText` / `View#setContentDescription` / `ImageView#setImageDrawable`），永远不会被混淆，但要按 View 类 / id 过滤。
- 用途提示（color 改色 / hide 隐藏显示 / text 换文字 / skip 跳过）是按记录类型、方法名、返回类型猜的，不保证。

**记录页顶部「范围」芯片**：任务内 → 任务外 → 全部，点一下切换，默认任务内。

**记录数量不对时先看这里：**
- 顶部概况行「已挡掉：触发窗口 N / 线程 N …」：被采集过滤挡掉的次数；记录不够先看是不是过滤开关挡掉了。
- 「各类记录」一行：每种记了多少，哪种满了会写「⚠满了，丢了 N 条新位置」。
- 方法追踪一条都没有：看顶部 ⚠；看类名有没有混淆变化；看是不是被触发窗口 / 排除名单挡了。

## 7. 功能清单（每个功能做什么）

### 7.1 采集（首页「记录哪些内容」）
| 功能 | 配置字段 | 说明 |
|---|---|---|
| 总开关 | `enabled` | 关了目标 App 暂停记录 |
| 记录范围 | `keywordMode` `keywords` `regex` | 全部文字 / 只记命中关键字的；关键字可按正则 |
| 谁设置的文字 | `traceSet`（细分：`setText` `setClear`） | `setText` / `append` / `setHint`；`setText` 空串或 null 单独记一类「清空文字」，看谁把文字清空了 |
| 谁画的文字 | `traceDraw`（细分：`drawTextView` `drawCanvas` `drawCompose`） | TextView 绘制、自绘 Canvas、Compose |
| 文字颜色 | `traceColor`（细分：`colorPaint` `colorSet`） | 画笔颜色 + `setTextColor` 设置位置 |
| 图标 / 按钮图片 | `traceIcons`（细分：`iconImage` `iconDesc`） | `ImageView.setImage*`（含 `AppCompatImageView.setImageResource`，记资源名）和 `View.setContentDescription`；截最长边≤64px 缩略图，同一位置留最近 3 种样子 |
| Compose 画笔参数 | `autoParams` `traceCompose` `composeObj` `composeDump` | 自动观察 `MultiParagraph.paint*`，和随后的 `drawText` 配对；记 this 身份；展开 MultiParagraph 字段（含文字） |
| 只设置、从未绘制的文字 | `traceSetOnly` `maxSetOnly` | 控件 INVISIBLE / GONE / 尺寸为 0 / 未挂窗口时不会 `onDraw`，靠这个才能看到；记录里给出没被画的原因 |
| 状态变化 | `traceState`（细分：`stateAlpha` `stateVisible` `stateSelected`） | `View.setAlpha / setVisibility / setSelected`，记谁改的和取值；alpha 按 0.1 一档去重 |
| 方法追踪 | `traceMethods` 等 | 见第 5 章 |
| 方法追踪独占 | `traceExclusive` | 见第 5 章 |
| 快速选择预设 | （界面按钮） | 只记文字（推荐）/ 只记方法追踪 / 全部打开 / 找钩子（最窄，只设置采集过滤）/ 关掉全部过滤 |

### 7.2 采集过滤（挡掉不相关的，在抓栈之前判断，被挡的只计数）
| 功能 | 字段 | 说明 |
|---|---|---|
| 触发窗口 | `windowMs`（0 / 1500 / 3000 / 5000）`windowAll` | 最近一次触摸后这段时间内才记；默认只管方法追踪，`windowAll` 让其他记录也受管。Dialog / PopupWindow 里的触摸看不到 |
| 排除通用基础设施 | `excludeInfra` | 不记 LiveData、Fragment 生命周期、字节异步包装等（方法追踪） |
| 线程 | `threadMode`（0 全部 / 1 主线程 / 2 后台） | 用 Looper 判断 |
| 只记带时间的调用 | `valueClock` | 参数或返回值里有 `00:00` 才记 |
| 压低高频方法 | `quietCount` `quietSpanMs` | 同一位置超过 N 次且持续超过一段时间后只计数、不抓栈 |
| 手写条件 | `threadFilter` `pageFilter` `viewFilter` `valueFilter` `excludeList` | 线程名 / 页面 / 控件 / 值匹配（时长自动展开，`01:37` 同时匹配 `97000`）/ 排除名单（`类#方法`、`类#*`、`#方法`、类名或包名前缀） |

### 7.3 记录是怎么存的
- 按位置合并：同一段代码设置 / 绘制的一批控件合成一条，记录里列出全部 id（最多 60 个）；文字内容不进 key，同一位置出现过的不同文字都会列出（最多 40 种）。
- 限流：同一位置前 `perKeyStacks`（默认 3）次抓栈，之后每 `sampleEvery`（默认 200）次抽一次；全局每秒最多 `stacksPerSec`（默认 1000）次抓栈兜底。
- 栈清洗：去 Hook 框架帧、尾部系统帧和通用基础设施帧，折叠 XML 布局加载栈。
- 按页面分别记录：每条记录带「页面」（Activity > Fragment），同一控件换页面另记一条。
- 屏幕可见性在写快照时才判断（● 在屏幕上 / ○ 不在 / ? 未知）。
- 分文件存（`splitFiles`，默认开）：主文件只放概况，每种记录一个文件；每种记录各自上限 `capTextView=800` `capCanvas=300` `capCompose=400` `capClear=300` `capIcon=300` `capState=300` `capTrace=600`；每种栈各自深度 `depthSet` `depthDraw` `depthColor` `depthIcon` `depthState`（0 = 用 `stackDepth`），方法追踪用 `traceStackDepth`（默认 30）。
- 落盘：事件触发 + 单次延迟 `flushSec`（默认 3 秒），没有轮询。配置热更新靠 inotify，改了配置约 2 秒内在目标 App 里生效，不用重启。
- 清空记录后，屏幕上已显示的静态文字会被主动重画一次，才能被记到。

### 7.4 时间线、标记、基线、任务
| 功能 | 字段 / 位置 | 说明 |
|---|---|---|
| 时间线 | `tlOn` `tlOps` `tlSamples`，细分 `tlTouch` `tlKey` `tlPage` `tlViewTree` `tlClass` `smpText` `smpState` `smpIcon` `smpTrace` | 把用户操作（点击 / 滑动 / 长按 / 返回，带坐标和点中的控件）、页面切换、钩点可用、各位置的记录样本、控件加入 / 移出视图树按毫秒排成一条；上限 3000 条，丢了多少会写出来 |
| 标记 | 记录页「更多 → 打标记」 | 在时间线上记一笔"现在开始做某某"；经 root 写进目标 App 的 `markers.log` |
| 基线 | 记录页「更多 → 基线：开始 / 结束」 | 录一段什么都不操作的时间，期间被调用的位置标"基线里也在调用" |
| 任务浮窗 | 首页「打开浮窗」/ 记录页「更多 → 任务浮窗」 | 浮在所有 App 上面，按任务清单一步一步提示；开始 / 结束 / 重做 / 中止都作为标记推给目标 App；每件事开始短震一下；显示「下一件」面板 |
| 任务内 / 任务外分桶 | `recOutside`（默认 `false`） | 默认只记「任务开始 → 任务结束」之间。任务之间、「暂停记录」期间是轻模式：不建记录、不记样本。开 `recOutside` 后任务外也记，但单独一桶（各自上限、各自文件 `.OUT`） |
| 自动结束 | （浮窗内置） | 每 3.5 秒读一次快照，记到事件且安静约 7 秒就自动结束；带秒数的到点就结束；一直没记到会用黄色字写出原因；最长 90 秒强制结束 |
| 没记录到的原因 | （浮窗内置） | 点下一件时先发结束标记，等约 5 秒落盘，经 root 读回快照检查；**必须这件事期间真有记录（不只是点击、页面切换）才算通过**，否则停下来写原因（读不到快照 / 目标进程没收到开始标记 / 这件事期间没事件 / 有操作但一条记录都没记到），「复制原因」发给 AI |
| 暂停记录 / 开始记录 | 浮窗内 | 暂停期间除标记、页面切换外什么都不记；用于下一件要翻很多界面 |
| 当前标识 | 方法追踪行 `@tag=N` | 比如视频 id；记录和事件都带，不同视频的记录靠它对上号 |

### 7.5 链路追踪（默认关，会拖慢目标 App，用完关掉）
| 字段 | 说明 |
|---|---|
| `chainOn` | 总开关；以方法追踪里的方法为锚点 |
| `chainAsync` | 上游：记下是谁在哪个线程用 Handler / 线程池投递的，最多追 6 层 |
| `chainEffects` | 下游·界面效果：锚点执行期间发生的 setText / 清空 / 图标 / 状态变化，及它投递的异步任务 3 秒内做的事 |
| `chainDown` | 下游·被调用的方法：锚点所在类和 this 里同包字段所属的类（最多 8 个类、300 个方法）被临时钩住 |
| `chainEvery` `chainMaxDown` | 采样：前 5 次每次建链，之后每 `chainEvery`（20）次一次；链里最多 `chainMaxDown`（120）个被调用方法 |
| `chainCoroutine` | 协程调度作为异步来源，尽力而为，类被混淆或没用协程时找不到 |

### 7.6 记录页
- 搜索框（支持 `re:` 正则，如 `re:\d{1,2}:\d{2}` 找时长）+ 筛选芯片：类型 / 页面 / 分类 / 排序 / 仅屏幕上 / 隐藏公共控件 / 范围。
- 类型多选，默认选中的类型 = 采集时打开的开关。「没显示的文字」不受「仅屏幕上」影响。
- 页面：点页面名 = 只看（导出也只含）这个页面；点铅笔或长按 = 起名，多个页面起同名会合成一类。
- 分类（几项同时选 = 同时满足）：所属容器 / 代码模块 / 控件类 / 屏幕位置。
- 隐藏公共控件：把多个页面里位置和文字都相同的（底部栏等）藏起来；不作用于方法追踪记录。
- 更多菜单：这些筛选是什么意思、粘贴命令、任务浮窗、编辑任务清单、打标记、基线开始 / 结束、查看时间线、清空所有记录。
- 详情页：概览（含用途 / 触发原因、首次 / 最近时间、调用间隔、基线分账、当前标识、this 身份、钩点信息、栈上各层出现次数、状态快照、链路追踪）/ 设置栈 / 绘制栈 / hook 签名。

### 7.7 首页其他
- 顶部：**粘贴配置和任务清单**（回填并保存 / 打开浮窗）。
- 「怎么用」三步卡片；「只应用设置，不清空记录」。
- 目标 App 包名（多个用逗号分隔）；底部「查看记录」「应用并重新记录」。
- 「高级」：抓栈参数、方法追踪、手写过滤条件，有「恢复默认参数」。
- 「更多细分项」：每种记录各自的上限、栈深度、Compose 展开等。
- 离开首页自动保存本地设置（不推送）。

## 9. 记录页「粘贴命令」（筛选已采集的记录，和采集配置是两件事）

记录页右上「更多 → 粘贴命令…」。一行 = 一套筛选条件，空格分隔多个 `key=value`；不带 `=` 的词当搜索词。执行时**先清空当前所有筛选再设置**。无法识别的 key 或不存在的 value 会被忽略并 toast 提示。

开放词表（大小写不敏感、子串匹配）：`container=` `module=` `view=` `page=` `owner=`（对象归属，1.29.0）`role=`（类角色：ViewHolder / Fragment / ViewModel / Listener / 数据实体 …）

封闭词表（必须照抄，小写）：

| key | 取值 |
|---|---|
| `kind` | `TEXTVIEW` `CANVAS` `COMPOSE` `ICON` `TRACE` `TEXTSET` `STATE` `all` |
| `zone` | `top` `bottom` `right` `bottomleft` `content` `offscreen` |
| `hook` | `biz`（有稳定业务帧）`widget`（只有通用控件帧）`obf`（只有混淆帧）`none` |
| `freq` | `once` `low`（2~10）`mid`（11~50）`high`（>50，多半列表项） |
| `reuse` | `local` `cross` `global` |
| `shape` | `empty` `duration` `number` `fixed` `dynamic` |
| `fresh` | `new` `recent` `old` |
| `purpose` | `color` `hide` `text` `skip` `other` |
| `baseline` | `noise` `live` `unknown` |
| `trigger` | `touch` `frame` `data` `msg` `sync` `none` |
| `tag` | 当前标识（如视频 id） |
| `grade` | 钩点评级（1.29.0）：`a` 覆写框架方法 `b` 稳定业务 `c` 通用 `d` 混淆 `x` 未知 |

## 10. 常见问题

| 现象 | 先查 |
|---|---|
| 一条记录都没有 | 模块是否在 LSPosed 启用并勾了目标 App？是否点了「应用并重新记录」？是否强杀后重开了目标 App？包名对不对？ |
| 记录太少 | 顶部「已挡掉」一行：触发窗口 / 线程 / 过滤是不是太严？`keywords` 写对了吗？ |
| 任务里没记到，浮窗黄字写了原因 | 点「复制原因」整段发给 AI；常见是目标进程没收到开始标记（目标 App 当时没在运行，或进程在标记发出之后才启动） |
| 冷启动最初几百毫秒记不到 | 钩子还没装上，做不到；只能记"用户在做冷启动" |
| 方法追踪装不上 | 看顶部 ⚠：类没找到（App 更新后混淆名会变）、方法不存在、hook 失败 |
| 目标 App 很卡 | 关掉全量模式、`autoParams`、链路追踪；方法追踪加 `@count` 或 `quietCount` |
| 换了目标 App 版本 | 混淆名会变，重新记一次 |
| 浮窗已开着，粘了新任务清单 | 先点浮窗 ✕ 关闭，再点「打开浮窗」，新清单才会生效 |
| 浮窗所在进程被杀、没发出"浮窗关闭" | 目标进程会一直停在"任务流程"状态（只记任务内）；强杀目标 App 重启后恢复 |

## 11. 已知限制

- Compose 没有 `setText`，只有绘制栈；Compose 也没有 View，控件增删样本对 Compose 无意义。
- 直接改 `Editable` 的文本变化（输入框里敲字）不会被记录。
- 图标只覆盖 `ImageView` 和有 `contentDescription` 的 View；纯 Canvas 画的位图 / 矢量暂不记录。
- 子类重写 `onDraw` 却不调用 `super.onDraw` 时，会被当成"从未绘制"。
- 协程、RxJava 的异步来源只有协程调度尽力而为；RxJava 没做。
- 栈上各层出现次数、每秒帧数是采样统计，不是真实调用次数。
- 链路追踪没有改 ART 的方法追踪；只有锚点执行期间 + 它投递的任务里发生的事才算下游。
- `类#*` 只含类自己声明的方法；构造方法不继承。
- 本模块只记录，不修改颜色或隐藏。
- **多个新功能（方法追踪继承方法、方法追踪独占、浮窗「下一件」、顶部粘贴框）没有在真机上验证过，也没有用 Android SDK 完整编译，只做过语法和符号检查。** 回复用户时如实说明。
